# MeetSpace Desktop 0.4.0

## Исходники

Интерфейс собран из ветки `codex/desktop-redesign-0.4.0`. Коммит установочных пакетов — `62d661f78ea67cc59a5a5e334d7f35bb67e059a3`. Контрольные измерения интерфейса, React и медиа сделаны на `acdfe343536c5300139f368d46361c2651c9a97c`. Между этими коммитами менялись тестовая самопроверка Windows и сценарий удаления NSIS, для обоих добавлены регрессионные проверки. React, медиатранспорт и платформенные параметры рабочего окна идентичны. Предыдущая версия для сравнения — `e332e3bfa9dc902039aa65aea3c990df61366fe1`, 0.3.4-beta.

Эталон — [janickiy/decs_maket](https://github.com/janickiy/decs_maket), коммит `3bc1fd561d7f1725bd32e352a4306228e745ae37`. Локальная страница на порту 8768 использует каталог `/Users/aleksandranickij/htdocs/decs_maket/meetspace-refresh-20261016`. Сверка опиралась на HTML, CSS, JavaScript и 50 снимков 25 состояний в светлой и тёмной темах. В пакетах работает один локально поставляемый React-интерфейс. Для его отображения пользователю не нужен сервер с макетом.

## Компоненты и оформление

Цветовые роли, типографика, размеры и состояния определены в `frontend/src/tokens.css`. В `desktop-workbench.css` высота верхней панели задана в 56 px, нижней в 28 px. Ширина боковой панели составляет 216 или 68 px в зависимости от окна. Тёмная тема имеет собственные цвета поверхностей, границ, текста и фокуса.

`EntryFrame` объединяет экраны до входа. `WorkspaceHeaderTitle` и `WorkspaceHeaderActions` размещают действия маршрута в верхней панели. `ChatInfoPage` отвечает за правую панель беседы. `ForwardMessagesDialog` обслуживает личные, групповые и конференц-чаты. `Switch` и `IconButton` используются совместно с существующими кнопками, полями, доступными диалогами, меню, аватарами и индикаторами загрузки. Удалены прежняя иллюстрация `AuthTeamVisual`, её стили, старое оформление переписки и правила для снятой разметки оболочки и мастера. Используемые системные диалоги и штатные элементы управления окнами сохранили поведение платформы.

## Действия с сообщениями

Из меню сообщения можно начать выделение, выбрать несколько сообщений, запустить удаление с подтверждением или открыть выбор получателя. Пересылка использует существующий серверный метод `POST /api/v1/conversations/{id}/messages/forward`, исходные идентификаторы и ключ повторного запроса. В результате сервер сохраняет происхождение сообщения и привязанные вложения. При частичной ошибке удаления интерфейс позволяет повторить оставшиеся операции. Доступ к сообщениям и файлам проверяется сервером. Проверки уведомлений покрывают личный чат и группу, режим без звука для конкретной беседы, повтор доставки события, отсутствие необязательного поля summary и явно отключённые параметры. В режиме закрытой встречи и при отсутствии прав доступные действия ограничены.

## Надёжность и границы доступа

На Windows обнаружена отдельная ошибка приёмки. Electron 44 не возвращает опцию `devTools` в диагностическом объекте окна. Самопроверка теперь вызывает `openDevTools()` и проверяет, создалось ли окно инспектора. Регрессионный тест различает оба режима. Параметры безопасности рабочего окна сохранены. Деинсталлятор Windows теперь удаляет регистрацию `meetspace://`, только если она по-прежнему указывает на его точную команду запуска. В тесте Windows 11 удалялась собственная команда. Другой EXE и иная команда с тем же EXE сохранились.

В ходе проверки исправлены дублирующая видеоплитка участника, обрезанный значок аватара группы, смещение переключателей уведомлений, доступность действий мастера при малой высоте и сброс тёмной темы при переходе из подключения ко входу. Изменение темы и представления комнаты не требует повторной публикации медиапотоков.

Сетевые контракты backend сохранены. В список разрешённых запросов Electron добавлены только необходимые методы обнаружения провайдера входа, восстановления и пересылки. Публичные запросы политики и восстановления не получают bearer или cookie. Авторизационные данные по-прежнему обрабатываются главным процессом, а HTTPS, sandbox, context isolation и ограничения preload остаются включёнными. Производственный LDAP-каталог и доставка реального письма внешнему получателю не использовались. Клиентские сценарии проверены на локальном сервере по фактическому контракту MeetSpace.

## Воспроизводимость проверок и ограничения

Номера исходных коммитов в профилях и снимках относятся к моменту их съёмки. Каждая версия использует общий frontend на всех платформах. Отдельный коммит `c7fb5ea` обновляет тест очистки временного профиля. Тест дожидается сохранения зашифрованной очереди выхода. Прежний тест однажды получил `ENOTEMPTY` при удалении рабочего каталога. Основной набор на релизном коммите прошёл при повторе, а исправленный сценарий прошёл 15 последовательных прогонов. Полный набор с исправленным тестом также прошёл. [Протокол релизного набора](desktop/artifacts/redesign-0.4.0/checks/release-unit-rerun.log) · [Набор с исправленным тестом](desktop/artifacts/redesign-0.4.0/checks/unit-after-fixture-fix.log) · [Повторная проверка очистки](desktop/artifacts/redesign-0.4.0/checks/broker-cleanup-repeated.log)

Сборки Windows и macOS поставляются по тестовому каналу без Authenticode и нотариализации Apple. Проверки Intel выполнены в Rosetta, проверки Windows x64 — в эмуляции Windows ARM. На Windows приёмка охватывала регистрацию ссылки и передачу её из командной строки. Запуск ссылки через ShellExecute, включение автозапуска пользователем, системное уведомление, трей, перетаскивание окна и полноэкранный режим остаются за рамками приёмки. Проверки Linux включали установку и запуск в указанных оконных системах. Системные уведомления, физический звук и демонстрацию экрана Linux в этих пакетах отдельно не проверяли. Восстановление пароля, корпоративный вход и мастер SSH проверены на локальных стендах.
