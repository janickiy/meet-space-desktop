# Desktop: отправка сообщений без цитаты

В 0.1.10-beta обычное сообщение в личном, групповом или конференционном чате могло завершаться общей ошибкой соединения до отправки HTTP-запроса. `ChatPanel` передаёт `replyTo: undefined`, когда пользователь не выбрал цитату. Electron IPC сохраняет это поле, а проверка JSON в main-процессе отклоняет `undefined`. Веб-запрос `JSON.stringify` пропускает такое поле.

В 0.1.11-beta общий desktop transport сериализует JSON до вызова IPC по тем же правилам, что и веб-запрос. Необязательные свойства пропускаются, выбранная цитата сохраняется, бинарные вложения передаются отдельно. Проверка тела, путей, авторизации и размеров в main-процессе остаётся обязательной.

Проверки:

- Регрессия воспроизведена до исправления: обычное сообщение из настоящей React-формы не достигает локального HTTPS API через production preload и broker.
- После исправления та же форма отправляет обычное сообщение и ответ с цитатой; сервер подтверждает получение, черновик и цитата очищаются.
- 48 unit/security-проверок проходят, включая JSON с необязательными полями, массивы, null, запрет несерилизуемых тел, бинарные запросы, ограничения IPC и локального протокола.
- `npm run test:product` включает реальную React-форму, sandboxed preload и broker с изолированным HTTPS-сервером. Это не проверка доставки на рабочем сервере или Windows runtime.

Нативная приёмка в Ubuntu и данные конкретной сборки сохраняются отдельно в `desktop/artifacts/`.
